# Bàn giao frontend – màn hình P0–P2 (quản trị, danh mục, món / công thức)

Dành cho: dev frontend làm mới giao diện theo mockup (`docs/mockup/`). Backend viết theo **khung code cũ** (D-30): route `api/<Controller>/<Action>`. Spec `DELICARE_API_Specification.md` chỉ mô tả nghiệp vụ; **URL, định dạng, mã lỗi lấy theo tài liệu này**.

Thử nhanh: `docs/api-tests/r1.0-foundation.http`, `docs/api-tests/r1.1-admin-masterdata.http` (VS Code REST Client). Swagger: `/swagger` (nhóm theo controller, có mô tả từng action).

## 1. Quy ước chung

### 1.1 Đăng nhập và thông tin phiên
| Việc | Gọi | Ghi chú |
|---|---|---|
| Đăng nhập | `POST api/Authentication/Login` JSON `{ "userName", "passWord" }` | Trả `data.token` (JWT) và `data.listMenu` (menu theo quyền). Gửi `Authorization: Bearer <token>` cho mọi request khác |
| Tải lại trang | `GET api/User/GetCurrent` | `{ user, listMenu }` – menu 2 cấp kèm cờ `allowAccess / allowAdd / allowEdit / allowDelete / allowPrint / allowExport / allowImport` để ẩn / hiện nút |
| Bộ chọn chi nhánh | `GET api/OrganizationUnit/GetBranches` | Đơn vị `UnitType = BRANCH` |
| Đổi mật khẩu | `PUT api/User/ChangePassword` (form `Id`, `PassWordOld`, `PassWordNew` ≥ 8 ký tự) | Lưu PBKDF2 thường, bỏ trạng thái mật khẩu tạm |
| Mật khẩu tạm (T45R.8, D-39) | Login trả thêm `data.mustChangePassword` | `true` → chuyển thẳng màn Đổi mật khẩu; mọi API khác trả **403** `{ responseCode: 403, responseMessage: "Cần đổi mật khẩu" }` trừ `User/ChangePassword`, `User/GetCurrent`, `Authentication/*`. Mật khẩu tạm quá 24 giờ → Login `code = 400`, `message = "Mật khẩu tạm đã hết hạn, liên hệ quản trị"`. Chi tiết mục 6 |
| Refresh token | **Chưa có** (GAP-AUTH-01) | Hết hạn (mặc định theo `Jwt:AccessTokenMinutes`) → đăng nhập lại |

### 1.2 Định dạng kết quả
Mọi action trả HTTP 200 với 1 trong 2 dạng (JSON camelCase):

```json
{ "responseCode": 200, "responseMessage": "Lấy thông tin dữ liệu thành công", "data": { } }
{ "responseCode": 200, "responseMessage": "…", "listData": [ ], "totalRecords": 125 }
```

| Tình huống | HTTP | Nội dung |
|---|---|---|
| Thành công | 200 | `responseCode = 200` |
| **Lỗi nghiệp vụ** (trùng mã, sai trạng thái, vi phạm quy tắc, không tìm thấy…) | 200 | `responseCode = 400`, `responseMessage` tiếng Việt – hiển thị nguyên văn cho người dùng |
| Thiếu / sai dữ liệu đầu vào (kiểu, độ dài) | 400 | Chuỗi `"Model State Invalid"` hoặc ProblemDetails |
| Chưa đăng nhập / token hết hạn | 401 | |
| Không có quyền | 403 | Ẩn nút theo cờ quyền ở `listMenu` để tránh |
| Lỗi hệ thống | 500 | Chuỗi `"Internal Server Error"`; tra log theo header `X-Correlation-Id` |

Không bao giờ có trường mật khẩu trong response.

### 1.3 Danh sách, chi tiết, thêm / sửa / xóa (mọi danh mục)
| Action | Cách gọi | Ghi chú |
|---|---|---|
| `GetAll` | GET, query: `SearchText`, các lọc `…Id` / `Status` / `…Type`, `Page` (từ 1), `PageSize` (≤ 1000), `SortField` (tên trường camelCase), `SortOrder` = `ascend` / `descend`; bảng có hiệu lực theo ngày thêm `EffectiveOn=YYYY-MM-DD` | `listData` có `stt` (số thứ tự) và nhãn của khóa ngoại (vd. `companyName`); `totalRecords` = tổng sau lọc |
| `GetById` | GET `?id=` | `data` = bản ghi |
| `GetAllData` | GET | Toàn bộ bản ghi chưa xóa – dùng cho dropdown |
| `Insert` | POST **form** (`application/x-www-form-urlencoded` hoặc `multipart/form-data`), tên trường = PascalCase hoặc camelCase của cột | Không gửi `Id` |
| `Update` | PUT **form**, kèm `Id` | **Ghi đè đủ trường**: gửi lại mọi trường của form, trường bỏ trống sẽ thành null |
| `Delete` | DELETE `?id=` | Xóa mềm. Đang được bảng khác tham chiếu → `responseCode 400` "Không thể xóa dữ liệu… đang được sử dụng" |

Cột NOT NULL của bảng phải gửi khi thêm / sửa. Thiếu cột này thì hiện tại trả 500 (hành vi cũ). Danh sách cột: `docs/reference/DB_SCHEMA_124.md`.

### 1.4 Trạng thái, dropdown dùng chung, lịch sử
| Việc | Gọi |
|---|---|
| Nhãn / màu trạng thái, bộ lọc trạng thái (47 bộ) | `GET api/MetaData/GetStatuses` (tất cả) hoặc `?key=Order.Status` / `?key=Order` |
| Danh mục tham chiếu chưa có bảng (MealType, CustomerType, SupplierType, WarehouseType, StorageType, WasteType, AdjustmentReason, ReturnInspectionResult, QcResult) | `GET api/MetaData/GetReferenceLists` hoặc `?name=MealType` |
| Dropdown từ bảng | `GET api/<Entity>/GetAllData` |
| Tab "Lịch sử xử lý" của 1 bản ghi | `GET api/AuditChange/GetAll?EntityName=<Entity>&IdChange=<Id>&Page=1&PageSize=20` |

`GetStatuses` và `GetReferenceLists` chỉ cần đăng nhập. Giá trị đều **PROPOSED – BA/PO CONFIRM**; đổi danh mục tham chiếu trong `appsettings.json` (`ReferenceLists`), không cần sửa code.

### 1.5 Phân quyền (D-31)
- Quyền = nhóm người dùng (`UserGroup`) × menu (`ObjectMenu`, `MetaLink = #/<screen-id>`), cờ `Allow*` trong `UserRole`. Admin (`isAdmin`) có mọi quyền.
- Quy tắc theo tên action: `Get*` → xem; `Insert` / `Create*` → thêm; `Delete*` → xóa; `Export*`, `Print*`, `Import*`; còn lại → sửa.
- **Duyệt**: cờ `allowEdit` trên mục menu "Duyệt – <màn hình>" (`MetaLink = #/wf-inbox?type=<screen-id>` – hộp duyệt lọc theo loại, nhóm "Phê duyệt"). Admin gán trên ma trận quyền như mọi menu.
- Chỉ admin: `User/ResetPassword`, `User/SaveIsAdmin`, `UserRole/GetPreview`, `AuditChange/DeleteData`, `LocationTracking/DeleteData`.

## 6. Người dùng 1 bước + mật khẩu tạm (T45R.8 – D-37, D-38, D-39)

Backend xong (T45R.8); màn hình làm cùng đợt FE (D-40). Thử nhanh: `docs/api-tests/t45r8-admin-users.http`.

### 6.1 Tạo người dùng 1 bước – `POST api/Person/Insert` (form)
Form `adm-user` → "Tạo mới" gồm Hồ sơ + Tài khoản, gọi **một** API:

| Trường | Bắt buộc | Ghi chú |
|---|---|---|
| `FullName`, `PhoneNumber`, `DateOfBirth`, `Sex`, `Address` | `FullName` (nếu không nhập `UserName`) | Hồ sơ `Person` |
| `UserName` | Không | Trống → tự sinh từ họ tên ("Phạm Văn Ngọc" → `ngocpv`, trùng thì `ngocpv1`…). Có → chữ thường không dấu, số, `. _ -`, 2–50 ký tự, không khoảng trắng, không trùng (không phân biệt hoa thường) |
| `ListUserGroupId` | Không | Id nhóm cách nhau dấu phẩy |
| `IsActive` | Không | `true` = dùng ngay. **Không gửi = `false`** (hành vi cũ) → form nên gửi rõ |

```json
{ "responseCode": 200, "responseMessage": "Lưu thông tin thành công",
  "data": { "personId": "…", "userId": "…", "userName": "ngocpv", "tempPassword": "Kq7mXa3RtZ9p" } }
```
Lỗi (`responseCode = 400`, không tạo gì): "UserName … đã tồn tại…", "Tên đăng nhập chỉ gồm chữ thường không dấu…", "Không tìm thấy nhóm người dùng", "Không tự sinh được tên đăng nhập…".

"Tạo tài khoản cho hồ sơ có sẵn": chọn hồ sơ bằng `GET api/Person/GetAllDataByKey?key=…&isEdit=false` (chỉ hồ sơ chưa có tài khoản) → `POST api/User/Insert` (form `UserName`, `PersonId`, `ListUserGroupId`, `IsActive`) → cùng dạng `data` như trên. Hồ sơ đã có tài khoản → 400 "Hồ sơ này đã có tài khoản đăng nhập (…) – mỗi hồ sơ chỉ có tối đa 1 tài khoản". Liên kết Employee ↔ User chưa có cột (GAP-ADM-03): nút "Lấy từ nhân viên" chỉ điền sẵn form.

### 6.2 Mật khẩu tạm
- `GET api/User/ResetPassword?id=<userId>` (chỉ admin) → `{ "responseCode": 200, "responseMessage": "Đặt lại mật khẩu thành công", "data": "Kq7mXa3RtZ9p" }`.
- Mật khẩu tạm 12 ký tự (chữ hoa, thường, số; không có 0 O 1 l I), hạn **24 giờ**, chỉ trả **một lần** (Person/Insert, User/Insert, ResetPassword). Hiện popup + nút Sao chép + cảnh báo "chỉ hiện một lần".
- Đăng nhập bằng mật khẩu tạm: response `data` có thêm `"mustChangePassword": true` (các trường cũ giữ nguyên) → chuyển thẳng màn Đổi mật khẩu.
- Trong lúc đó mọi API khác trả HTTP **403** body `{ "responseCode": 403, "responseMessage": "Cần đổi mật khẩu", "data": false }`; được gọi: `User/ChangePassword`, `User/GetCurrent` (có `mustChangePassword`), `Authentication/*`.
- `PUT api/User/ChangePassword` thành công → mật khẩu thường; token hiện tại dùng bình thường ngay (không bắt đăng nhập lại).
- Quá 24 giờ: Login trả `{ "code": 400, "message": "Mật khẩu tạm đã hết hạn, liên hệ quản trị" }` → admin reset lại.
