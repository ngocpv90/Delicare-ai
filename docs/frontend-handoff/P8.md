# Bàn giao frontend – Pilot P8: giao vận, đối soát suất, phản ánh (T19)

Quy ước chung (đăng nhập, định dạng `Result` / `Results`, lỗi nghiệp vụ `responseCode = 400`, quyền theo `listMenu`, CRUD chuẩn): xem `P0-P2.md` mục 1. Thử nhanh: `docs/api-tests/p8-delivery.http`.
Form gửi số dạng `62.5` (dấu chấm), ngày `yyyy-MM-dd`, ngày giờ `yyyy-MM-ddTHH:mm:ss` (GAP-FORM-01). Ảnh / chữ ký: tải file trước (DocumentFile), API chỉ nhận **đường dẫn**.

Màn hình FE-P8: `log-route` (lập chuyến, nhiệt độ xuất phát, xuất phát, in biên bản) – mục 1; `log-execution` / `log-pod` (đến điểm, bàn giao + POD, thất bại – trên ngăn kéo chi tiết chuyến) – mục 2; `crm-reconciliation` (suất thực tế phục vụ) – mục 3; `log-complaint` – mục 4.
Ngoài Pilot (chưa có API): xếp hàng lên xe (`log-loading`), `log-execution` theo DeliveryExecution, tách / chuyển đơn giao, thu hồi khay, cảnh báo SLA tự động, báo cáo suất theo điểm.

### 1.1 Chi tiết chuyến (`data`)
| Trường | Ý nghĩa |
|---|---|
| `route` | Bản ghi `DeliveryRoute`: `routeNo` (`CX-YYMMDD-<XE>-NN`), `deliveryDate`, `vehicleId`, `driverId`, `plannedStart`, `actualStart`, `actualEnd`, `status`, `name` |
| `statusName` | Kế hoạch / Đang xếp / Đang giao / Hoàn thành |
| `vehicleCode, licensePlate, capacity, driverName` | Xe, tài xế (Employee) |
| `loadMeals, loadPercent` | Σ suất kế hoạch các điểm; % tải = ÷ `Vehicle.Capacity` × 100 (null nếu xe chưa có tải) |
| `deliveryTempMinC, departureTemperatureC` | Ngưỡng (60) và nhiệt độ xuất phát đo gần nhất |
| `listStop[]` | `id, sequenceNo, stopStatus / statusName` (Kế hoạch / Đã đến / Đã giao / Thất bại), `customerId, customerName, deliveryLocationId, locationName, address, orderId, orderNumber, deliveryOrderId, deliveryNumber` (`PH-…`), `plannedArrival, actualArrival, plannedMealQty, deliveredMealQty, shortageQty` (thiếu + / thừa −), `handoverTemperatureC`, `pod` (bản ghi POD: `deliveredQuantity, acceptedQuantity, rejectedQuantity, receiverName, receiverPhone, receivedAt, signatureUrl, photoUrl, remark`), `note`, `allowedActions[]` (`arrive`, `recordTemperature`, `deliver`, `fail`) |
| `listEvent[]` | Dòng thời gian `DeliveryEvent`: `eventType` (TEMP_CHECK / DISPATCHED / ARRIVED / DELIVERED / FAILED), `eventAt, deliveryStopId, temperatureC, latitude, longitude, photoUrl, description, recordedBy` |
| `listBatch[]` | Mẻ nấu của ngày / ca phục vụ chuyến: `id, batchNumber` (`ME-…`), `dishName, status, statusName, sampleRetained` |
| `listBlocker[]` | (Kế hoạch / Đang xếp) điều kiện xuất phát còn thiếu – hiện đỏ, khóa nút Xuất phát |
| `allowedActions[]` | Kế hoạch: `recordTemperature, dispatch, update, delete, exportDeliveryNote`; Đang xếp: `recordTemperature, dispatch, exportDeliveryNote`; khác: `exportDeliveryNote` |
| `listWarning[]` | Cảnh báo của thao tác vừa làm (vượt tải, xe đã có chuyến khác chưa xong, sản xuất chưa sẵn sàng, nhiệt độ dưới ngưỡng, giao thiếu, đã tạo phản ánh…) |

### 1.2 Lập chuyến – `POST DeliveryRoute/Create` (JSON)
```json
{ "deliveryDate": "2026-12-21", "shiftId": "<ca>", "vehicleId": "<xe>", "driverId": "<nhân viên – tùy chọn>",
  "plannedStart": null, "plannedEnd": null, "name": null, "description": null, "listOrderId": ["<orderId>", "..."] }
```
- `listOrderId` trống = mọi đơn chờ xếp chuyến của ngày / ca. Đơn không hợp lệ → 400 nêu số đơn + lý do.
- Số chuyến `CX-YYMMDD-<mã xe>-NN` (mã xe = `Vehicle.Code`, trống thì biển số; bỏ dấu, chỉ A–Z 0–9). Xe `Status` Maintenance / Inactive → 400.
- Mỗi đơn → 1 đơn giao `PH-YYMMDD-NNNN` + 1 điểm dừng: suất kế hoạch = tổng suất đơn, giờ dự kiến = ngày + `DeliveryWindowFrom` của điểm giao, thứ tự theo giờ dự kiến. `plannedStart` trống = giờ dự kiến sớm nhất − 60′.
- Trả chi tiết (mục 1.1) + `listWarning`.

### 1.3 Xuất phát – điều kiện chặn (GAP-DLV-03, D-42)
Kế hoạch / Đang xếp → **Đang giao** (`actualStart`; đơn giao → Đang giao; sự kiện DISPATCHED). Có `TemperatureC` thì ghi lần đo xuất phát trước. **Chặn** (400, thông báo liệt kê đủ lý do) khi:
1. Nhiệt độ xuất phát **gần nhất** < 60 °C hoặc chưa đo.
2. Còn mẻ của ngày / ca chưa **Đã đóng gói** (hoặc Không đạt) – nêu số `ME-…` và trạng thái; chưa có mẻ nào.
3. Có mẻ (không bị loại) **chưa lưu mẫu thức ăn** – "Mẻ chưa lưu mẫu thức ăn (bắt buộc trước khi giao): ME-…" → ghi lưu mẫu ở `prod-batch` (`ProductionBatch/RecordSampleRetained`, nay ghi được cả khi mẻ Đã đóng gói).
Nếu lần gọi này có `TemperatureC` < 60 (kèm khắc phục): lần đo **vẫn được lưu**, `responseCode = 400`, `responseMessage` bắt đầu "Đã lưu lần đo nhiệt độ.", `data` = chi tiết chuyến.

## 2. `log-execution` / `log-pod` – Thực hiện giao tại điểm (chuyến Đang giao)

| Chức năng (spec 10.3) | Action | Quyền | Ghi chú |
|---|---|---|---|
| Đến điểm | `POST DeliveryStop/Arrive` (form `Id, TemperatureC?, CorrectiveAction?, Latitude?, Longitude?, PhotoUrl?, Note?`) | Edit `log-stop` | Kế hoạch → Đã đến. Trả chi tiết **chuyến** |
| Bàn giao + POD | `POST DeliveryStop/Deliver` (form `Id, TemperatureC?, CorrectiveAction?, DeviceCode?, DeliveredQuantity, AcceptedQuantity?, ReceiverName, ReceiverPhone?, ReceivedAt?, SignatureUrl?, PhotoUrl?, Remark?`) | Edit `log-stop` | Mục 2.1 |
| Giao thất bại | `POST DeliveryStop/Fail` (form `Id, Reason, Latitude?, Longitude?`) | Edit `log-stop` | Kế hoạch / Đã đến → Thất bại; đơn giao Thất bại; **đơn hàng giữ Đang sản xuất** → xếp chuyến giao bù |
| Danh sách POD | `GET ProofOfDelivery/GetAll` | View `log-pod` | Thêm / sửa / xóa POD qua CRUD → 400 |
| Sự kiện | `GET DeliveryEvent/GetAll` | View `log-event` | Thêm qua CRUD → 400 |
| Sửa điểm dừng | `PUT DeliveryStop/Update` (form `Id, SequenceNo, PlannedArrival, Note`) | Edit | Chỉ chuyến + điểm Kế hoạch; thứ tự không trùng |

### 2.1 Bàn giao (BUSINESS_RULES §7, §8b)
- Nhiệt độ bàn giao **gần nhất tại điểm** (gửi kèm `TemperatureC` hoặc đo trước bằng `RecordTemperature` có `DeliveryStopId`) phải ≥ 60 °C; chưa đo / dưới ngưỡng → 400 (lần đo dưới ngưỡng kèm khắc phục vẫn lưu, như 1.3). Không bàn giao được → `Fail` để giao bù.
- `DeliveredQuantity` > 0; `AcceptedQuantity` (trống = bằng số giao) từ 0 tới số giao; `ReceiverName` bắt buộc.
- Ghi POD (`rejectedQuantity` = giao − nhận); điểm → Đã giao (`deliveredMealQty`, `shortageQty` = kế hoạch − giao); đơn giao → Đã giao; sự kiện DELIVERED.
- Mọi đơn giao còn hiệu lực của đơn hàng đã giao → **đơn hàng Đã giao** (sẵn sàng đối soát). Mọi điểm xong → **chuyến Hoàn thành**.
- Có suất bị từ chối → tự tạo phản ánh `PA-…` (kênh POD, loại SHORTAGE, mức Medium) – `listWarning` nêu số phản ánh.

## 3. `crm-reconciliation` – Đối soát suất

| Chức năng (spec 6.7) | Action | Quyền | Ghi chú |
|---|---|---|---|
| Đơn chờ đối soát | `GET OrderReconciliation/GetPendingOrders?MealDate=&CustomerId=` | View | `listData[]`: `orderId, orderNumber, mealDate, customerId, customerName, orderStatus, orderedQuantity, deliveredQuantity, podAcceptedQuantity, reconciliationId?, reconciliationStatus?` (đơn **Đã giao**) |
| Danh sách | `GET OrderReconciliation/GetAll` | View | CRUD sinh mã |
| Chi tiết | `GET OrderReconciliation/GetDetail?id=` / `GetByOrder?orderId=` | View | Mục 3.1 |
| Ghi suất thực tế phục vụ | `POST OrderReconciliation/Reconcile` (form `OrderId, ServedQuantity, ReturnedQuantity?, WastedQuantity?, Remark?`) | Edit | Đơn Đã giao, có POD. 0 ≤ phục vụ ≤ Σ suất nhận (POD); phục vụ + trả về + hủy ≤ suất nhận. Ghi lại được tới khi đóng |
| Đóng đối soát | `POST OrderReconciliation/Close` (form `Id, Remark?`) | Edit | Khớp / Chênh lệch → Đóng; **đơn hàng → Đã đối soát**. \|Chênh lệch %\| > 1% → bắt buộc ghi chú |
| Thêm / sửa / xóa qua CRUD | – | – | → 400 |

### 3.1 Chi tiết đối soát (`data`) – công thức (PROPOSED – GAP-DLV-05)
| Trường | Ý nghĩa |
|---|---|
| `reconciliation` | `orderedQuantity` (suất đặt), `deliveredQuantity` (Σ giao theo POD), `acceptedQuantity` (= **suất phục vụ**), `varianceQty` = phục vụ − đặt, `variancePercent` (2 số lẻ), `status` (Matched khi chênh 0 / Variance / Closed), `finalAmount`, `proofOfDeliveryId`, `reconciliationDate`, `remark` |
| `orderNumber, orderStatus, mealDate, customerName, orderTotalAmount` | Đơn |
| `podAcceptedQuantity, servedQuantity, returnedQuantity, wastedQuantity, leftoverQuantity` | Suất nhận khi bàn giao, phục vụ, trả về, hủy, còn lại = nhận − phục vụ |
| `billingBasis, billingQuantity` | Cơ sở tính tiền (`BusinessRules:ReconciliationBillingBasis`, mặc định SERVED) và số suất tính tiền; `finalAmount` = giá trị đơn × suất tính tiền ÷ suất đặt (làm tròn đồng) |
| `listPod[], allowedActions[]` | POD của đơn; `reconcile, close` khi chưa đóng |

Ví dụ tính tay: đặt 60, giá trị 1.800.000; giao 58, nhận 56; phục vụ 50 → chênh −10 (−16,67%), tính tiền 1.800.000 × 50 ÷ 60 = **1.500.000**.

## 4. `log-complaint` – Phản ánh khách (cơ bản)

| Chức năng (spec 10.5) | Action | Quyền | Ghi chú |
|---|---|---|---|
| Danh sách | `GET CustomerComplaint/GetAll` | View | CRUD sinh mã (lọc trạng thái / mức độ / khách). Quá hạn: so `slaDueAt` với giờ hiện tại khi chưa Đã xử lý / Đóng / Từ chối |
| Chi tiết + lịch sử | `GET CustomerComplaint/GetDetail?id=` | View | `complaint`, `statusName`, `severityName`, `customerName, orderNumber, deliveryNumber, routeNo, assignedToName`, `isOverdue`, `listHistory[]` (`eventType` CREATED / ASSIGNED / COMMENT / RESOLVED / CLOSED / REJECTED, `oldStatus, newStatus, comment, eventAt, actorId`), `allowedActions[]` |
| Tạo | `POST CustomerComplaint/Create` (form `CustomerId, OrderId?, DeliveryStopId?, DeliveryOrderId?, DeliveryRouteId?, ProductionBatchId?, SourceChannel?, CategoryCode?, Severity?, Description, ReceivedAt?`) | Add | Số `PA-YYMMDD-NNNN`; mức độ High / Medium / Low (mặc định Medium; nhận cả HIGH / high / Cao…); hạn xử lý = lúc nhận + 4 / 24 / 72 giờ. Liên kết phải cùng khách; điểm dừng → tự điền đơn giao / chuyến / đơn hàng; mẻ → thêm "[Mẻ ME-…]" vào mô tả |
| Giao xử lý | `POST CustomerComplaint/Assign` (form `Id, AssignedTo?, Comment?`) | Edit | Mới / Đang xử lý → Đang xử lý; `AssignedTo` = User.Id (trống = người thao tác) |
| Đã xử lý | `POST CustomerComplaint/Resolve` (form `Id, Comment`) | Edit | Đang xử lý → Đã xử lý; `Comment` = cách xử lý (bắt buộc) |
| Đóng | `POST CustomerComplaint/Close` (form `Id, Comment?`) | Edit | Đã xử lý → Đóng |
| Từ chối | `POST CustomerComplaint/Reject` (form `Id, Comment`) | Edit | Mới / Đang xử lý → Từ chối (lý do bắt buộc) |
| Ghi chú | `POST CustomerComplaint/AddComment` (form `Id, Comment`) | Edit | Không đổi trạng thái |
| Sửa | `PUT CustomerComplaint/Update` | Edit | Chỉ phân loại / kênh / mô tả / mức độ (tính lại hạn) khi Mới / Đang xử lý |
| Thêm / xóa qua CRUD | – | – | → 400 |

`allowedActions`: Mới → `assign, reject, addComment, update`; Đang xử lý → `assign, resolve, reject, addComment, update`; Đã xử lý → `close, addComment`.
