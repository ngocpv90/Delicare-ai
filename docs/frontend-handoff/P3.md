# Bàn giao frontend – Pilot P3: thực đơn tuần, phân công thực đơn, đơn hàng (T13 + T46B.1)

Quy ước chung (đăng nhập, định dạng `Result` / `Results`, lỗi nghiệp vụ `responseCode = 400`, quyền theo `listMenu`, CRUD chuẩn): xem `P0-P2.md` mục 1. Thử nhanh: `docs/api-tests/p3-menu-order.http`.

Mã loại suất (`MealType`): `SANG`, `TRUA`, `TOI`, `DEM` (`api/MetaData/GetReferenceLists` → `MealType`). Thứ (`DayOfWeek`): 1 = Thứ 2 … 7 = Chủ nhật. Lựa chọn (Lựa chọn 1 / 2 / 3) = `MenuLine.SequenceNo` (GAP-MENU-01). Trạng thái: `api/MetaData/GetStatuses` (Menu, Order).

## 1. `menu-menu` – Thực đơn tuần

| Chức năng (spec 6.2) | Action | Quyền | Ghi chú |
|---|---|---|---|
| Danh sách / chi tiết / thêm / sửa / xóa | `Menu/GetAll`, `GetById`, `Insert`, `Update`, `Delete` (form) | View / Add / Edit / Delete | Thêm mới luôn `Status = Draft`, `VersionNo = 1` (bỏ qua Status gửi lên). Sửa chỉ khi Nháp / Đã duyệt, không đổi trạng thái. Xóa chỉ khi Nháp |
| Lịch tuần | `GET Menu/GetCalendar?id=&mealType=&sellingPrice=&customerId=&contractId=&on=` | View | `data.listRow[]` = hàng (mealType, optionNo, dishCategoryName) × `cells["1".."7"]` = danh sách món `{ menuLineId, dishId, dishCode, dishName, portionQty, costPerMeal, costComplete }`. `data.listTotal[]` = theo (mealType, optionNo, dayOfWeek): `costPerMeal`, `costComplete`, `foodCostPercent`, `foodCostOverTarget` (so `foodCostTargetPct`, mặc định 55). FC% chỉ có khi biết giá bán: `sellingPrice` nhập tay hoặc tra giá theo `customerId` (+ `contractId`) và `mealType` |
| Thêm / sửa / bỏ món | `MenuLine/Insert`, `Update`, `Delete` (form: `MenuId, DishId, MealType, DayOfWeek, SequenceNo, SortOrder, PortionQty, IsRequired, Note`) | màn `menu-menu-line` | Chỉ khi thực đơn Nháp / Đã duyệt. `DayOfWeek` 1–7, `SequenceNo` 1–9, `MealType` bắt buộc. Món chưa có công thức đang khóa → **vẫn lưu**, `responseMessage` có "Cảnh báo: …" (hiển thị dạng cảnh báo vàng) |
| Duyệt | `POST Menu/Approve` (form `Id, Note`) | **Approve** – mục "Duyệt – Thực đơn & phiên bản" | Nháp → Đã duyệt, cần ≥ 1 món |
| Công bố | `POST Menu/Publish` (form `Id, Note`) | Edit | Đã duyệt → Đã công bố. Mỗi thứ trong hiệu lực phải có ≥ 1 món cho mỗi loại suất đã gán; thiếu → thông báo liệt kê "TRƯA: Thứ 3, Chủ nhật" |
| Hết hiệu lực | `POST Menu/Expire` (form `Id, Note`) | Edit | Đã duyệt / Đã công bố → Hết hiệu lực |
| Sao chép | `POST Menu/Clone` (form `Id, Code, Name, EffectiveFrom, EffectiveTo`) | Add | Bản nháp mới kèm mọi món; trả `data` = Menu mới |
| In "Thực đơn gửi khách" | `GET Menu/ExportForCustomer?id=&project=` | Export | Trả file `.xlsx` (tải về). Lỗi nghiệp vụ (vd. chưa có món) trả JSON `responseCode = 400` – kiểm `Content-Type` |

## 2. `menu-assignment` – Phân công thực đơn

| Chức năng (spec 6.3) | Action | Quyền | Ghi chú |
|---|---|---|---|
| CRUD | `MenuAssignment/GetAll`, `GetById`, `Insert`, `Update`, `Delete` (form: `CustomerId, ContractId, MenuId, DeliveryLocationId, MealType, EffectiveFrom, EffectiveTo, Status`) | View / Add / Edit / Delete | `DeliveryLocationId` trống = gán cấp khách. Kiểm: hiệu lực từ ≤ đến; hợp đồng thuộc khách và có suất `MealType`; điểm giao thuộc khách; **không chồng hiệu lực** với phân công Active cùng (khách, điểm giao, loại suất). Status mặc định `Active` |
| Thực đơn áp dụng | `GET MenuAssignment/Resolve?customerId=&deliveryLocationId=&mealType=&date=` | View | `data = { menuId, menuCode, menuName, menuAssignmentId, level: LOCATION / CUSTOMER }`. Chỉ thực đơn Đã duyệt / Đã công bố. Không có → `responseCode = 400` |

## 3. `crm-order` – Đơn hàng

Trạng thái: `Draft` (Nháp) → `Submitted` (Đã gửi) → `Confirmed` (Đã xác nhận) → `Locked` (Đã chốt) → … ; `Cancelled` (Hủy).
**Giờ chốt** của ngày ăn D = **20:00 ngày D-1** (giờ VN, cấu hình `BusinessRules:OrderCutoffHourPreviousDay`). Mọi đơn trả `cutoffAt`, `isAfterCutoff`, `allowedActions` – dùng để ẩn / hiện nút.

| Chức năng (spec 6.6) | Action | Quyền | Ghi chú |
|---|---|---|---|
| Danh sách | `Order/GetAll` (SP cũ: `CustomerId, ContractId, DeliveryLocationId, OrderNumber, Status, …`) | View | |
| Chi tiết | `GET Order/GetDetail?id=` | View | `{ order, statusName, customerName, locationName, contractNumber, listLine[{ id, contractMealId, mealType, mealName, shiftId, shiftName, menuId, menuCode, quantity, unitPrice, lineAmount }], cutoffAt, isAfterCutoff, allowedActions[], pendingApprovalId, pendingApprovalNo }` |
| Khung tạo đơn | `GET Order/GetNewTemplate?customerId=&mealDate=` | View | Hợp đồng Active tại ngày ăn (không có → 400 "không có hợp đồng đang hiệu lực"). `listLocation[]` (mỗi điểm giao = 1 đơn; `existingOrderId` nếu đã có đơn) × `listLine[]` (`contractMealId, mealType, mealName, shiftId/Code/Name, unitPrice, priceSource, menuId, menuCode, suggestedQuantity = 0`) |
| Tạo đơn | `POST Order/Create` **JSON** `{ customerId, contractId?, deliveryLocationId, mealDate, deliveryDate?, note, listLine:[{ contractMealId, shiftId?, quantity, note? }] }` | Add | 1 đơn = 1 điểm giao. Dòng số lượng 0 bị bỏ, cần ≥ 1 dòng > 0. Số đơn `PH-YYMMDD-NNNN`. Đơn giá, thực đơn, ca mặc định tự điền. Trùng đơn (khách, điểm giao, ngày) chưa hủy → 400. Sau giờ chốt → 400. Trả `data` = chi tiết đơn (+ `listWarning` nếu loại suất chưa được gán thực đơn) |
| Sửa số suất | `PUT Order/UpdateLines` **JSON** `{ id, note?, listLine:[{ id, quantity }] }` | Edit | Nháp / Đã gửi / Đã xác nhận, trước giờ chốt. `quantity = 0` = bỏ dòng. **Đơn Đã xác nhận lệch > 30%** (dòng bất kỳ) → không ghi, tạo yêu cầu duyệt: `data.approvalRequested = true`, `responseMessage` có số XN-. Khi đang chờ duyệt không sửa tiếp được |
| Gửi | `POST Order/Submit` (form `Id, Note`) | Edit | Nháp → Đã gửi, trước giờ chốt; mọi dòng có loại suất, ca, số lượng > 0 |
| Xác nhận | `POST Order/Confirm` (form `Id, Note`) | Edit | Đã gửi → Đã xác nhận, trước giờ chốt |
| Chốt 1 đơn | `POST Order/Lock` (form `Id, Note`) | Edit | Đã xác nhận → Đã chốt, bấm được bất kỳ lúc nào |
| Nút "Chốt đơn 20h" | `POST Order/LockByMealDate` (form `MealDate`) | Edit | Chỉ khi đã tới giờ chốt của ngày đó. Khóa mọi đơn Đã xác nhận; trả `{ lockedCount, listLockedNumber, listNotConfirmedNumber, listPendingApprovalNumber }` – hiển thị danh sách đơn chưa xác nhận để xử lý tay |
| Hủy | `POST Order/Cancel` (form `Id, Reason`) | Edit | Nháp / Đã gửi (kể cả sau giờ chốt), Đã xác nhận (chỉ trước giờ chốt). Lý do bắt buộc (≥ 3 ký tự) |
| Duyệt lệch suất | `GET ApprovalRequest/GetMyPending?type=crm-order`, `POST ApprovalRequest/Decide` (form `Id, Approve, Note`) | mục "Duyệt – Đơn đặt suất ăn" (`#/wf-inbox?type=crm-order`) | Duyệt → ghi số suất đề xuất, tính lại tiền. Từ chối (bắt buộc lý do) → giữ số cũ. Đơn bị chốt / sửa sau khi gửi duyệt → không duyệt được ("Nội dung chứng từ đã thay đổi") |
| CRUD cũ | `Order/Insert` → 400 (dùng `Create`). `Order/Update` chỉ sửa `Note`, `DeliveryDate` của đơn Nháp. `Order/Delete` chỉ đơn Nháp. `OrderLine/Insert/Update/Delete` → 400 (dùng `Create` / `UpdateLines`) | | |

Chưa có trong Pilot (DEFERRED(PILOT)): số lượng gợi ý theo dự báo, lệch dự báo > 10% khi xác nhận, dạng kanban (`view=board`), sửa đơn sau giờ chốt qua duyệt (`ORDER_CHANGE_AFTER_CUTOFF`), đẩy thực đơn qua Zalo.
